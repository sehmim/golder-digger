The brief, line by line

Left is what the original document asked for. Right is what exists now, and the measurement that drove the change.

Fit Score“92%”, shown per candidate
Split into two scores, and never shown as a percentage. Fit is an internal gate — the geometric mean of harmony, rhythm and role, so one catastrophic component can’t be masked by two good ones. Novelty is separate. a single percentage implies a calibration that nothing in the system earns
Redefined
Four dialsfor user input
One dial, DISTANCE, redefined from “distance in embedding space” to a target novelty percentile among candidates that already fit. It selects a band, not a radius — DISTANCE 70 means the 70th percentile of non-obviousness, not 0.7 cosine. raw cosine 0.24 vs 0.48 has no perceptual meaning; a percentile does
Redefined
Graph databasefor similarity
Dropped. A graph built by linking each embedding to its nearest neighbours is a discretised copy of the same vector space, and inherits its pathologies. Storage is SQLite plus one NumPy matrix; each query is a single matmul. at 2,122 chunks the whole corpus loads into a (N, 512) array
Dropped
Chunk by barsespecially for long pieces
Built, and it fires far less than expected. At or under 12s, or with fewer than two downbeats, a file passes through whole — most of a sample library is already the atomic unit. bar-sliced: 36 of 2,043 files (1.8%) here, 60 of 8,394 (0.7%) on the one-shot library
Built
Key, mode, BPMmatch parts on musical metadata
Built as soft evidence, never a hard filter. An unconfident key estimate falls back to neutral instead of excluding a candidate, and tempo is ratio-aware so 87 against 174 is a match. real key estimates beat chance 5.5×, tempo 16× — see below
Built
“Vibe”a similarity axis
A CLAP embedding, but deliberately not used as a similarity ranking. It feeds Novelty only; compatibility is computed from musical features. “Sounds like” and “works with” are treated as different questions. 512-d embedding, L2 norm 1.000, verified on device
Redefined
ModesIonian, Super Locrian…
Major and minor only. The seven-mode detection in the brief’s output table isn’t implemented, and the key estimator isn’t accurate enough yet to carry that resolution. pitch class + mode lands 13.3%, the weakest measured figure
Not built

None implemented. Role (drums / bass / melody / harmony / texture / vocal / fx) is assigned by filename keyword, not by a classifier — which is a known weak point, not a finished feature. filename matching leaves 428 of 2,181 chunks (20%) with no role at all

Not built. The API streams a raw WAV with no time-alignment to the session tempo, so you can’t yet judge the combination — only imagine it. This is the largest gap between the brief and the build. GET /chunk/{id}/audio returns the clip unmodified

The one that flipped

“This would also work in abandoned projects”

In the original brief that was a closing aside — one sentence after the main pitch. It now looks like the strongest thing in the project, because it is the one capability that the commercial tools in this space don’t have. Ableton, Splice and Output all search libraries. None of them search your own unfinished work.

So the digging is now literal. A Live set is gzipped XML, which means an abandoned project can be read without opening it: session tempo, declared key, and every sample it references. Across the archive on this machine that’s 437 readable sets holding 30,912 sample references — a corpus of your own history that no sample marketplace can offer.

One project alone yielded 380 sample references, 371 of which still resolve on disk — even though the set was saved on a Windows machine and every absolute path inside it points at a C:/Users/… directory that doesn’t exist here.

Does the extraction actually work

The filenames in this library carry their own answers — EP1_Loop01_76_Cm.wav is 76 BPM in C minor. That’s free ground truth for the two fields the extractors are least trusted on. Running the same harness over mock features gives a chance-level control.

The last row is the one that matters most. key_confidence is supposed to be high when the key estimate is right and low when it isn’t. On mock features the separation is negative — the number is noise. On real features, correct estimates carry 0.277 confidence against 0.067 for wrong ones — a fourfold ratio. The confidence is informative, which is what lets an unsure estimate fall back to neutral instead of poisoning the harmony score.

The dial does what it claims

Is this just inverse similarity

The sharpest objection to the whole idea: that “compatible but non-obvious” is an elaborate way of sorting a similarity list backwards. 60 contexts × 5 dial positions × 6 strategies, 1,800 selections. Overlap is Jaccard against what Gold Digger returned for the same context and setting.

The objection doesn’t hold. Gold Digger and inverse similarity agree on only 26.6% of what they return, steady across the whole dial. Three-quarters of the output is material that walking outward in embedding space never surfaces. And at identical achieved novelty the gate keeps fit at 0.644 against 0.545, with nothing below the floor where inverse similarity puts 26.3% below it. Removing only the gate — keeping the band and the diversity term — costs 0.086 of fit and changes about 40% of the selection, so the gate is doing work rather than decorating.

The most useful result is a negative one. Nearest-neighbour retrieval scores the lowest fit of any strategy, below random. It returns the context’s own role 96.3% of the time at 0.891 intra-set redundancy — eight near-identical items. A similarity search hands you another snare when what you wanted was something to sit next to the snare. That is the empirical case for keeping “sounds like” and “works with” apart.

What isn’t answered yet

The baselines are internal. Nobody has listened to a single result.

Every number on this page is computed inside the scoring model. The baselines establish that the strategies are genuinely different and that the gate holds compatibility while the dial moves — they cannot establish that the results are more inspiring, because that is a judgement only a producer can make. A system can be measurably distinct and still creatively useless.

The second missing piece is a listener. Fit and novelty are currently tuned by constants that were guesses — FIT_FLOOR, BANDWIDTH, REDUNDANCY. They can only be set by ear, and nobody has heard a result yet, because tempo-synced audition doesn’t exist.

Next, in order

Listeners decides everything

Rate obviousness, compatibility and inspiration across the five dial positions, blind and in random order. The one question the internal numbers cannot reach.

Tempo-synced audition MUST ×3

Time-align the candidate to the session tempo before playback. Without it nobody can judge a suggestion, so no constant can be tuned.

Mode detection

Major/minor lands at 13.3%, barely above the 4.2% chance line and the weakest number here. Pitch class is fine; quality is not.

Role tagging

A fifth of the corpus has no role, and mock mode hid that by inventing one. The sample folders are already organised by role — better evidence than filenames.
